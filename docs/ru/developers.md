# Разработка адаптера, сервиса или Skill

Перед созданием файлов необходимо выбрать слоев, которые будут использоваться для хранения данных. DCC-MCP поддерживает использование публичных адаптеров DCC, приватных сервисов, не связанных с DCC, а также специализированных пакетов услуг. Для этого достаточно использовать локальную папку или внутренний источник данных.

## Выберите один из вариантов развития.

| Ваше потребности | Маршрут |
|---|---|
| Подключите Maya, Blender, Unreal или любой другой процесс-хост. | Используйте `dcc-mcp-creator`, чтобы создавать или улучшать адаптеры DCC. |
| Разработай внутреннюю API, командную оболочку, базу данных активов, сервис для рендеринга или сервис для проведения обзоров. | Нужно использовать `dcc-mcp-creator` с персонализированным идентификатором сервиса и параметром `instance_type="standalone"`. Не требуется использование какого-либо публичного репозитория. |
| Добавьте типовую рабочую процедуру к уже существующему адаптеру или самостоятельной службе. | Используйте `dcc-mcp-skills-creator`. Не создавайте другой рендеринга-модуль. |
| Изменить геффекты, CLI-протокол, уровень безопасности или поведение между различными хостами. | Предоставьте этот общий контракт в распоряжение Core. |

Перед созданием публичного адаптера или функции Skill необходимо проверить каталог [экосистемы](/ru/ecosystem). Приватные идентификаторы сервисов не требуют наличия записей в публичном каталоге.

## Создайте частную службу, не связанную с протоколом DCC.

Используйте этот путь для внутренней системы, которая не является творческим приложением и не использует GitHub. Запустите агент разработки из частного проекта, а затем использовать следующий запрос:

```text
Используй dcc-mcp-creator для среды выполнения и dcc-mcp-skills-creator для файлов Skill. Работай только в текущем закрытом проекте. Сохрани принятые в нём язык, менеджер пакетов, тесты, способы аутентификации и развёртывания. Не создавай репозиторий GitHub, публичную запись в каталоге, внешнюю задачу или открытый выпуск.

Выбери реальный внутренний процесс и реализуй минимальный сервис с постоянным идентификатором и одним типизированным Skill только для чтения. Используй DccServerBase и DccServerOptions.from_env(..., instance_type="standalone") без dcc_pid. При разработке принимай соединения только через петлевой интерфейс. Выполняй обычные операции с сервисами, файлами и API напрямую. Добавляй диспетчер или мост только для перехода между потоками или процессами. Определи закрытые схемы входа и выхода, все аннотации безопасности, тайм-аут, пример вызова и понятные ошибки с удалёнными конфиденциальными данными. Храни учётные данные в принятой в проекте системе управления секретами.

Запусти dcc-mcp-cli lint skills и минимальный тест проекта. Запусти сервис и выведи фактический URL /mcp. В официальном MCP Inspector проверь tools/list, поиск и загрузку нужного Skill, describe, корректный вызов, ошибку при неверном вводе и штатное завершение. Повтори сценарий в CLI командами list, load-skill, describe и call с параметром --output toon. Сохрани полученные slug и request_id. Не подставляй значения наугад и не повторяй запросы вслепую. Перечисли изменённые файлы, результаты проверок и оставшиеся задачи по безопасности и развёртыванию. Остановись перед публикацией или изменением общей инфраструктуры.
```

Необходимая проверка:

1. Существующие правила проектирования используются повторно.
2. Указан номер службы, предназначенной для обработки заказов. Также указано, почему робот-программист работает в режиме „`standalone`“.
3. Один из навыков был подтвержден как эффективный; ещё один разговор прошел успешно, при этом информация передавалась только в read-only формате.
4. Один из безопасных вариантов обработки некорректных входных данных.
5. Оставлены чистые следы завершения процесса работы, а также непрерывный путь личной доставки.

### Запустите пример сервиса.

Полный пример кода находится по адресу [`examples/remote-server`](https://github.com/dcc-mcp/dcc-mcp-core/tree/main/examples/remote-server). Название директории, в которой находится этот пример, остается неизменным. В данный момент этот пример работает как самостоятельное сервисное устройство; он обнаруживает директорию с набором функций, предоставляемых этим сервисом.

```bash
pip install dcc-mcp-core
dcc-mcp-cli lint skills
python server.py
```

Ожидается, что вывод после запуска будет включать URL-адрес вроде `http://127.0.0.1:8765/mcp`, пользовательское имя `studio-service`, а также режим работы приложения `standalone`.

### Используйте контейнер для разработки.

В примере используется конфигурация [развивающего контейнера](https://containers.dev/). Спецификации и референсы для CLI являются открытым исходным кодом. Поэтому тот же самый Python, Node.js, Core и Inspector могут работать в совместимом редакторе или через оболочку агента, без необходимости использования хостинга.

Из корневого репозитория:

```bash
npm install --global @devcontainers/cli
devcontainer up --workspace-folder examples/remote-server
devcontainer exec --workspace-folder examples/remote-server python server.py
```

Используйте второй терминал для автоматического отслеживания дыма.

```bash
devcontainer exec --workspace-folder examples/remote-server \
  npx --yes @modelcontextprotocol/inspector@latest --cli \
  http://127.0.0.1:8765/mcp --transport http --method tools/list
```

Лаборатория работает под управлением не корневого пользователя. Кроме того, в лаборатории не создается сокет хост-контейнера. Секретные данные следует хранить в защищенном месте, не в составе образа системы.

Для групповой обучения, проводимого в браузере, сервис [Educates](https://docs.educates.dev/en/stable/) предоставляет возможность проведения отдельных сессий, шаги для выполнения задач в формате Markdown, терминалы, а также встроенный редактор. Для работы сервиса необходимы специалисты, которые разбираются в таких технологиях, как Kubernetes, ingress, идентификация пользователей, установление лимитов, использование изображений и очистка сессий после их завершения. Если необходимы некоторые общие сервисы, можно использовать локальный Dev Container.

### Тестирование с использованием MCP Inspector

Используйте официальный сервис [MCP Inspector](https://github.com/modelcontextprotocol/inspector). Этот сервис работает локально; для его использования не требуется какого-либо хост-аккаунта. Сервис поддерживает протокол Streamable HTTP. Кроме того, существует возможность использования приватного локального сервиса, который не подключен к публичной сети Интернета.

```bash
npx --yes @modelcontextprotocol/inspector@latest
```

Соединяемся с печатной URL-адресой `/mcp`. Поискаем запись с именем `hello-world`, загружаем её, а затем вызываем метод `hello_world__greet` с параметром `{"name":"Agent"}`. Также необходимо отправить пустое имя, чтобы проверить, является ли ответ структурированным или нет.

::: warning Зачем использовать местного инспектора?
Хостированный игровой сервер не может получить доступ к сервису типа MCP, работающему в локальной сети. Для внутренних систем лучшим решением является использование локального программного обеспечения от открытого исходного кода. Никогда не выводить процесс, создаваемый таким сервером, вне зоны безопасности.
:::

### Проверьте это через CLI.

Используйте CLI после того, как сервис зарегистрируется. Сохраняйте данные, полученные в результате поиска.

```bash
dcc-mcp-cli list --output toon
dcc-mcp-cli load-skill hello-world --dcc-type studio-service --output toon
dcc-mcp-cli describe <tool-slug-returned-by-load> --output toon
dcc-mcp-cli call <tool-slug-returned-by-load> --json '{"name":"Agent"}' --wait --output toon
```

## Как изменить навык, не добавляя при этом время выполнения действия?

Используйте этот призыв, когда runtime уже существует.

```text
Используй dcc-mcp-skills-creator в текущем закрытом проекте. Сначала найди существующие Skills, затем добавь или доработай тот, который отвечает за нужный процесс. Не создавай новый адаптер, сервис, репозиторий или открытый пакет. В SKILL.md в разделе metadata.dcc-mcp.* укажи типизированные схемы, аннотации безопасности, affinity, timeout, call_examples и next-tools. Реализуй один скрипт с ограниченной областью действия и используй dcc_mcp_core.skills_helper для готовых функций. Выполни dcc-mcp-cli lint для устанавливаемого каталога, загрузи Skill в существующую среду и проверь один правильный и один ошибочный ввод. Приведи результаты и запроси моё согласие перед публикацией.
```

Используйте следующую последовательность действий: **поиск существующих прав собственности → редактирование или изменение данных → проверка на наличие ошибок → перезагрузка данных → загрузка новых данных → описание данных → вызов соответствующих функций → диагностика проблем».

## Не нужно пытаться вычислять, что произошло с кодом, просто проведите отладку.

| Симптомы | Далее проверяем… |
|---|---|
| Проверка навыков не удается. | Прежде чем начать выполнение программы, необходимо устранить конкретную проблему, связанную с использованием инструмента `dcc-mcp-cli lint`. |
| Сервис не отвечает на запросы пользователей. | Проверьте напечатанный URL. Затем выполните запросы `GET /v1/healthz` и `GET /v1/readyz`. |
| Нет навыков. | Проверьте родительскую путь, затем выполните команду `reload-skills`. После этого снова попробуйте найти нужный элемент. |
| Необходимый инструмент отсутствует. | Загрузите нужный навык, а затем следуйте за возвращаемым значением `next_step`. |
| Передача звонка не происходит. | Сохраняйте значение `request_id`. Затем выполните команду `dcc-mcp-cli doctor` для получения информации о неудачах. После этого исправьте проблему, связанную с той лейлом, которая отвечает за эти неудачи. |
| Частная зависимость недоступна. | Отчитайте внутреннего владельца и скрывайте имеющиеся доказательства. Не открывайте никаких публичных вопросов. |

## Переход от локальных успехов к частной доставке

Необходимо продолжать разработку в локальной сети. Для доступа к интранет-ресурсам необходимо использовать протокол TLS, а также механизмы авторизации, списки разрешений для доступа к сети, управление секретами, хранение данных для аудита и контроль за выключением системы. Можно использовать существующие инструменты проекта: архивы, контейнеры, частные реестры или внутренние системы развертывания. GitHub является необязательным решением.
