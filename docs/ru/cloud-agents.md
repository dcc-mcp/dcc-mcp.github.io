# Облачные агенты и DCC-MCP

Необходимо выбрать подходящую систему для обработки данных DCC-MCP. Для этого необходимо учитывать результаты тестирования существующих программного обеспечения, интерфейсы платформы, необходимые условия для установки и ограничения, связанные с развертыванием системы.

DCC-MCP позволяет соединять ИИ-агента с творческими приложениями с помощью специальных инструментов, таких как MCP и `dcc-mcp-cli`. Облачный агент может анализировать документы, вносить изменения в них, экспортировать нужные элементы и проверять результаты своей работы, при условии, что в его окружении есть соответствующие приложения, функциональные адаптеры и авторизованное соединение. Агент, способный использовать интерфейс CLI и HTTP-гейт, может работать без необходимости использования настроек MCP.

В этом руководстве рассматриваются такие платформы, как **OpenAI dots**, **Grok Bot**, **Meta Muse** (персональный агент) и **Manus Cue**. Документация по этим платформам хранится отдельно от тестов, на одном компьютере, используемом для работы с Lightbox. Lightbox представляет собой контекст разработки и развертывания приложений; DCC-MCP обеспечивает интеграцию приложений с другими платформами. Результаты работы этого компьютера не подтверждают поддержку всех аккаунтов, изображений или платформ. Это независимые интеграции, и не существует никаких обязательств по партнерству с какой-либо платформой.

## Выберите подходящую связь. {#choose-a-connection}

1. Применение в облачном компьютере агента: используйте поддерживаемый локальный адаптер, а также CLI или клиент MCP окружения. Сначала необходимо проверить версии программного обеспечения и адаптеров. Наиболее полезными являются нативные API для выявления подходящих решений для интеграции; далее следует использование типизированных адаптеров.
2. **Применение на авторизованной рабочей станции:** Необходимо сохранять точку доступа DCC в режиме loopback. Связь между устройствами должна осуществляться через одобренные компьютерные соединения или защищенные шлюзы. Агент в облаке должен иметь доступ к нужным путям для хранения проектов и артефактов. Кроме того, рабочая станция должна оставаться в рабочем состоянии.
3. Агенты, способные использовать Shell: для инвентаризации, узкие диапазоны инструментов и выполнения других операций используется утилита `dcc-mcp-cli`. Нативный интерфейс для настройки MCP является необязательным. Командный интерфейс и CLI являются разными средствами взаимодействия с системой. Bridge `translate` в Core использует протокол `stdio → HTTP`. Поддержка командного интерфейса не подтверждает возможность использования стандартного протокола DCC для работы с данными.

Для подключения между сетями настройте **TLS и аутентификацию на входном прокси или отдельном шлюзе OAuth**. Ограничьте доступ и привяжите DCC только к петлевому интерфейсу. Согласно [спецификации аутентификации Core 0.20.39](https://github.com/dcc-mcp/dcc-mcp-core/blob/v0.20.39/docs/guide/remote-server.md#auth), встроенная проверка Bearer/OAuth/CIMD для каждого запроса в `McpHttpServer` пока только запланирована. `ApiKeyConfig` и `OAuthConfig` сами по себе не обеспечивают защиту работающего сервиса. Не публикуйте незащищённую конечную точку как сервис с аутентификацией.

## Предварительные требования к установке {#prerequisites}

- Необходимо получить разрешение на установку или обновление программного обеспечения в выбранной среде. Также необходимо иметь доступную целевую приложение и все необходимые лицензии. Плагин DCC-MCP не включает в себя само приложение, его лицензию или публичный узел для множества пользователей.
- Это версия приложения, соответствующая требованиям, предусмотренным в функциональных возможностях данного адаптера. Для использования этой версии приложения необходимы нативные библиотеки, а также официальный адаптер или сигнатура исходного кода, проверенная должным образом.
- Необходимо наличие совместимой конфигурации CLI/MCP, готовной инстанции и авторизованного проектного каталога. Также инструменты, которые зависят от графического интерфейса, должны иметь возможность использования управляемого рабочего стола или поддерживаемых служб отображения информации.
- Для использования в режиме удаленного доступа необходимо наличие поддерживаемой инфраструктуры для обработки TLS/АUTH-запросов, а также секретов, управляемых оператором. В этом руководстве не предусмотрено создания публичного эндпоинта или обработки учетных данных.

Следуйте инструкциям по настройке [общего агента](/ru/agents) и [директории адаптера](/ru/ecosystem). Инструкции по установке и решение проблем, связанных с конкретными хостами, находятся в репозитории адаптера.

## Рабочая процедура с проверкой {#verified-workflow}

Начните с документа, связанного с определенной задачей, а также с одной операции. Например, можно провести проверку CAD-детали, внести изменения в ее размеры, сохранить измененную версию документа, затем снова открыть ее и проверить размеры перед экспортом в формат STEP. Это пример процесса принятия решений; вышеупомянутая матрица показывает, какие из экспериментов были успешными.

```bash
# After approved setup, inspect the current environment and live instances.
dcc-mcp-cli doctor
dcc-mcp-cli list

# Only continue when a ready instance for the intended application exists.
dcc-mcp-cli search --query "inspect document" --dcc-type freecad

# Follow the returned next_step and exact schema; do not invent a tool slug.
```

Стопить процесс при наличии пустого инвентаря или если экземпляр не готов к работе. Необходимо сохранить версии приложения/адаптера/Ядра, пути подключения, информацию о ветках кода, идентификаторы запросов/задач, а также результаты проверок артефактов. Сохранение данных должно быть проверено путем повторного открытия соответствующего документа или индивидуальной проверки выходных данных. Необходимо сохранить идентификатор неудачной задачи перед ее диагностикой; не следует слепо повторять процесс изменений.

```text
Используйте навык dcc-mcp для проверки документа, принадлежащего заданию, на выбранном облачном компьютере или авторизованной рабочей станции. Проверяйте версии документа и его готовность к использованию. Используйте соответствующие инструменты для выполнения одной операции. Сохраните результаты работы и снова откройте их. Проверьте также экспортированный файл. Перед установкой какого-либо программного обеспечения или изменением состояния системы обязательно сообщите об этом. Уведомите также о маршруте подключения, имеющихся доказательствах и оставшихся ограничениях.
```

## Часто задаваемые вопросы {#faq}

### Значит ли это, что все четыре платформы поддерживают все функции DCC?

Нет. Интерфейсы платформ, установленное программное обеспечение и готовность адаптеров являются отдельными элементами. Grok Bot и Muse описали способы интеграции, но не провели никаких тестов на функциональность этих инструментов. Неизвестны также требования к интерфейсам, необходимым для использования Cue. Даже если провести какие-либо тесты, это будет только в отношении записанных версий и рабочих процессов Cue.

### Могу ли я использовать DCC-MCP без использования нативного экрана настроек MCP?

Да, когда агент получает разрешение на доступ через шарлатанский интерфейс, тогда работающий инструмент `dcc-mcp-cli` становится возможным. Также необходимо, чтобы локальный или защищенный HTTP-гateway был доступен. Необходимо проверить, разрешает ли платформа необходимые действия и соединения. Однако сам по себе шарлатанский интерфейс не позволяет установить или лицензировать приложение.

### Почему нормальное выполнение кода может происходить, в то время как MCP не может этого сделать?

Некоторые команды могут создавать файлы в случае, когда процесс обработки данных, проверка результатов, отслеживание задач или проверка происхождения исходного материала не проходят успешно. FreeCAD и Inkscape позволяют учитывать такие ошибки. Необходимо рассматривать сбои в работе адаптера как нерешенные до тех пор, пока все этапы процесса не будут выполнены успешно.

### Может ли агент, работающий в облаке, работать с моим лицензированным настольным устройством DCC?

Авторизованное подключение к персональному компьютеру или защищенный шлюз может обеспечить такой маршрут. Необходимо уточнить вопросы, связанные с доступом, поддерживаемыми версиями программ, маршрутами передачи данных, доступность рабочих станций и условиями лицензирования с оператором. Документация платформы не подтверждает, что все настольные компьютеры подходят для использования в данной системе.

### Будет ли этот страница способствовать повышению видимости поиска с помощью ИИ?

Нет. В [рекомендациях Google по поиску с ИИ](https://developers.google.com/search/docs/appearance/ai-features) речь идёт о доступном для обхода и чтения содержимом и структурированных данных, соответствующих видимым фактам. Специальный файл или схема для ИИ не требуются. Индексация и показ не гарантируются. В [документации OpenAI](https://developers.openai.com/api/docs/bots) различаются поисковые роботы и роботы, собирающие данные для обучения. Здесь действуют существующие правила сайта для роботов.
