# 클라우드에서 제작 도구 연결하기

DCC-MCP를 사용하기 위해서는, 구버전의 소프트웨어나 플랫폼 인터페이스, 설치에 필요한 조건들, 그리고 배포에 대한 제한 사항들을 고려하여 적절한 클라우드 또는 워크스테이션 워크플로우를 선택해야 합니다.

DCC-MCP는 AI 에이전트를 타입된 도구, MCP, 그리고 `dcc-mcp-cli`를 통해 창의적인 애플리케이션과 연결합니다. 클라우드 기반의 에이전트는 문서를 검사할 수 있으며, 특정 부분을 수정하거나 자산을 내보낼 수 있습니다. 또한, 환경에 적합한 애플리케이션과 작동하는 어댑터, 그리고 권한이 있는 연결이 있다면 결과를 확인할 수도 있습니다. 셸 기능을 지원하는 에이전트는 MCP 설정 화면 없이도 CLI와 HTTP 게이트웨이를 사용할 수 있습니다.

이 가이드는 **OpenAI Dots**, **Grok Bot**, **Meta Muse**(개인 에이전트), 그리고 **Manus Cue**를 다룹니다. 이들 플랫폼에 대한 문서들은 Lightbox 작업을 위해 사용되는 컴퓨터에서 별도로 기록됩니다. Lightbox는 여기서 개발 및 배포가 이루어지는 환경입니다. DCC-MCP는 애플리케이션의 통합을 담당합니다. 이 컴퓨터에서 얻은 결과는 모든 계정, 이미지, 플랫폼에 대한 지원을 보장하지 않습니다. 이러한 통합들은 별도로 이루어지며, 어떤 플랫폼과의 파트너십도 존재하지 않습니다.

## 증거의 수준 {#evidence-levels}

검토된 증거는 **2026-10-01 UTC**에 대한 것입니다. 설치된 애플리케이션, CLI 카탈로그 항목, 그리고 작동하는 MCP 도구의 호출은 서로 다른 개념입니다.

| 라벨/제목 | 증거가 무엇을 보여주는지 |
| --- | --- |
| MCP 테스트를 통과했습니다. | 지정된 어댑터와 연결 장치가, 해당 환경에서 명명된 워크플로우를 완료했습니다. 실험적인 버전이나 미공개된 패치들도 여전히 존재합니다. |
| **오직 네이티브 언어로만** | 해당 애플리케이션은 자체 CLI/API를 사용하여 일종의 아티팩트를 생성하거나, 간단한 API 검증을 통과했습니다. 하지만 DCC-MCP의 승인을 받았다는 의미는 아닙니다. |
| 공식적인 인터페이스가 제공됩니다. 하지만 DCC 방식은 아직 테스트되지 않았습니다. | 플랫폼 문서에는 통합 기능을 제공할 수 있는 인터페이스에 대한 설명이 있습니다. 이는 실현 가능성에 대한 평가일 뿐, 실제로 테스트된 DCC 워크플로우는 아닙니다. |
| **확인되지 않았습니다.** | 필요한 인터페이스나 애플리케이션의 동작 방식이 아직 정해지지 않았습니다. |

불완전하거나 거부된 MCP 워크플로우는, 중간 파일이 생성되었다 하더라도 “공백”으로 보고됩니다. 어댑터 리포지토리는 자신들의 설치 및 버전 지원을 담당합니다. 이 페이지는 클라우드 워크플로우에 대한 정보를 요약한 것입니다.

## 클라우드 MCP 테스트 {#cloud-mcp-tests}

다음과 같은 문제들은 **2026-10-01 UTC**에 클라우드 테스트 담당자가 해결했습니다. 두 개의 MCP 폐쇄 루프가 로컬 수정 후에 해결되었으며, 하나의 Blender 호환성 테스트는 지원 기준을 충족하지 못했습니다. 또한, 하나의 Inkscape 생산 워크플로우도 계속해서 문제가 남아 있었습니다. PC8에서의 웹사이트 구축 및 브라우저 테스트 결과는 별도의 문서에 기록되어 있습니다. 이러한 결과들은 일반적인 지원 인증을 의미하지 않습니다. ## 연결 방식을 선택하세요. {#choose-a-connection}

1. **에이전트의 클라우드 컴퓨터에서의 적용:** 지원되는 로컬 어댑터와 CLI, 또는 환경의 MCP 클라이언트를 사용해야 합니다. 먼저, 어떤 애플리케이션과 어댑터 버전을 사용할지 확인해야 합니다. 네이티브 API는 통합 가능한 제품을 찾는 데 유용합니다. 그 다음으로는 타입화된 어댑터를 사용하는 방법이 있습니다.
2. **승인된 워크스테이션에서의 사용:** DCC 엔드포인트를 루프백 모드로 설정하고, 승인된 컴퓨터 연결이나 보호된 게이트웨이를 통해 연결해야 합니다. 클라우드 에이전트는 해당 프로젝트와 아티팩트에 대한 접근 권한이 필요하며, 워크스테이션은 항상 사용 가능해야 합니다.
3. **셸-capable 에이전트:** 인벤토리 관리, 도구 검색 및 호출을 위해 `dcc-mcp-cli`를 사용합니다. 네이티브 MCP 구성 UI는 선택적인 기능입니다. 명령어 MCP와 CLI는 별개의 인터페이스입니다. Core의 `translate` 브리지는 **stdio → HTTP**로 작동하며, 클라이언트의 명령어 지원은 DCC stdio 워크플로우를 지원하지 않습니다.

서로 다른 네트워크에서 연결할 때는 **앞단 프록시 또는 전용 OAuth 게이트웨이에서 TLS와 인증을 적용**하세요. 접근 범위를 제한하고 DCC는 루프백에만 바인딩하세요. [Core 0.20.39 인증 명세](https://github.com/dcc-mcp/dcc-mcp-core/blob/v0.20.39/docs/guide/remote-server.md#auth)에서 `McpHttpServer`의 요청별 Bearer/OAuth/CIMD 검사는 아직 계획 단계입니다. `ApiKeyConfig`와 `OAuthConfig`만으로는 런타임 접근을 통제할 수 없습니다. 인증을 구성하지 않은 엔드포인트를 공개 서비스로 노출하지 마세요.

## 설치에 필요한 조건들 {#prerequisites}

- 선택된 환경에서 소프트웨어를 설치하거나 업데이트할 수 있는 권한이 필요합니다. 또한, 사용할 수 있는 타겟 애플리케이션과 필요한 라이선스도 있어야 합니다. DCC-MCP 플러그인에는 해당 애플리케이션, 라이선스, 또는 공개된 다중 사용자용 엔드포인트가 포함되어 있지 않습니다.
- 소유하는 어댑터가 지원하는 범위 내의 애플리케이션 버전이어야 하며, 네이티브 라이브러리가 필요합니다. 또한, 공식적으로 인증된 어댑터나 명시적으로 기록된 소스 패치도 필요합니다.
- 호환되는 CLI/MCP 연결, 준비된 실제 인스턴스, 그리고 승인된 프로젝트 디렉터리가 필요합니다. GUI 기반의 도구들도 플랫폼이 제공하는 관리형 데스크톱이나 지원되는 디스플레이 서비스가 필요합니다.
- 원격 사용을 위해서는, 승인된 TLS/암호 인프라와 운영자가 관리하는 비밀 정보가 필요합니다. 이 가이드에서는 공개 엔드포인트나 자격 증명을 제공하지 않습니다.

[공유 에이전트 설정](/ko/agents)과 [애드이터널 디렉토리](/ko/ecosystem)를 따르세요. 설치 방법 및 호스트별 문제 해결 방법에 대한 정보는 애드이터널 리포지토리에 남아 있습니다.

## 검증이 포함된 워크플로우 {#verified-workflow}

먼저, 작업에 관련된 문서와 하나의 작업을 시작합니다. 예를 들어, CAD 부품을 검사하고, 치수를 변경한 후, 그 결과를 저장하고, 다시 열어서 치수가 올바른지 확인한 다음, STEP 형식으로 내보냅니다. 이는 승인 패턴입니다. 위의 표에서는 실제로 통과된 실험들이 무엇인지 나타나 있습니다.

```bash
# After approved setup, inspect the current environment and live instances.
dcc-mcp-cli doctor
dcc-mcp-cli list

# Only continue when a ready instance for the intended application exists.
dcc-mcp-cli search --query "inspect document" --dcc-type freecad

# Follow the returned next_step and exact schema; do not invent a tool slug.
```

재고가 비어 있거나, 인스턴스가 준비되지 않았다면 작업을 중단해야 합니다. 애플리케이션/애드온/코어 버전, 연결 경로, 패치와 관련된 소스 커밋 정보, 요청/작업 ID, 아티팩트 정보 등은 반드시 보관해야 합니다. 저장되거나 내보낸 내용은 네이티브 문서를 다시 열거나, 출력 결과를 직접 확인함으로써 검증해야 합니다. 실패한 작업의 ID는 분석하기 전에 반드시 보관해야 합니다. 맹목적으로 변경 사항을 다시 적용해서는 안 됩니다.

```text
dcc-mcp 스킬을 사용하여, 선택된 클라우드 컴퓨터나 권한이 부여된 워크스테이션에서 해당 작업에 관련된 문서를 확인할 수 있습니다. 버전과 준비 상태를 확인하고, 필요한 도구를 사용하여 변경 사항을 적용합니다. 그런 다음 결과를 저장하고 다시 열어서 결과가 올바른지 확인해야 합니다. 소프트웨어를 설치하거나 시스템 상태를 변경하기 전에는 반드시 확인해야 합니다. 연결 경로, 관련 증거, 그리고 남아 있는 제한 사항에 대해서도 보고해야 합니다.
```

## 자주 묻는 질문들 {#faq}

### 이것은 네 개의 플랫폼 모두가 모든 DCC 기능을 지원한다는 의미인가요?

아니요. 플랫폼 인터페이스, 설치된 소프트웨어, 어댑터의 적합성은 별개입니다. Grok Bot과 Muse는 통합 방법을 문서화했지만, DCC 테스트는 이루어지지 않았습니다. Cue가 필요로 하는 인터페이스도 아직 확인되지 않았습니다. 심지어 간단한 테스트라도, 그 테스트는 기록된 버전과 워크플로우에만 적용됩니다.

### DCC-MCP를 사용할 때, 네이티브 MCP 설정 화면이 없이도 사용할 수 있을까요?

네, 에이전트가 셸 액세스를 허용했다면, 작동하는 `dcc-mcp-cli`와 접근 가능한 로컬 또는 보호된 HTTP 게이트웨이가 필요합니다. 또한, 해당 플랫폼이 필요한 실행 및 연결을 허용하는지 확인해야 합니다. 셸만으로는 애플리케이션을 설치하거나 라이선스를 부여할 수 없습니다.

### 왜 네이티브 실행이 성공할 수 있는 반면, MCP는 실패하는 걸까요?

원시 명령어는, 어댑터의 처리 과정, 결과 검증, 작업 추적 또는 소스 출처 확인 등이 실패할 경우에도 파일을 생성할 수 있습니다. FreeCAD와 Inkscape는 이러한 문제들을 해결하는 데 도움을 줍니다. 어댑터의 실패는, 입력된 워크플로우와 결과물이 모두 정상적으로 처리되기 전까지는 해결되지 않은 상태로 간주됩니다.

### 클라우드 에이전트가 내가 가지고 있는 라이선스가 부여된 데스크톱 DCC와 함께 작동할 수 있을까요?

승인된 개인용 컴퓨터 연결이나 보호된 게이트웨이를 통해 그러한 경로를 제공할 수 있습니다. 접속 가능 여부, 지원되는 버전, 경로, 워크스테이션의 가용성, 라이선스 관련 사항 등은 운영자와 반드시 확인해야 합니다. 플랫폼의 설명서에는 모든 데스크톱 DCC에 대해 보장된 정보가 포함되어 있지는 않습니다.

### 이 페이지가 AI 검색 기능의 가시성을 보장할 수 있을까요?

[구글의 AI 검색 가이드라인](https://developers.google.com/search/docs/appearance/ai-features)에 따르면, 일반적으로 접근 가능하고 읽을 수 있는 콘텐츠와 구조화된 데이터가 필요합니다. 특별한 AI 파일이나 스키마는 필요하지 않으며, 인덱싱이나 표시도 이루어지지 않습니다. [오픈AI의 크롤링 문서](https://developers.openai.com/api/docs/bots)에서는 검색 크롤링과 훈련용 크롤링을 구분하고 있습니다. 이 가이드라인은 사이트의 기존 크롤링 정책을 유지합니다.
