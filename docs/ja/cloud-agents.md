# クラウドで制作ツールに接続する

DCC-MCPのために、クラウドやワークステーションを利用したワークフローを選択してください。その際には、使用されているソフトウェアのバージョン、プラットフォームのインターフェース、インストールに必要な条件、およびデプロイメントの制限などを考慮する必要があります。

DCC-MCPは、AIエージェントを、タイプ入力ツールやMCP、そして`dcc-mcp-cli`を通じて、創造的なアプリケーションに接続します。クラウド上のエージェントは、ドキュメントを検査したり、編集を行ったり、アセットをエクスポートしたりすることができます。また、その環境が適切なアプリケーションや動作するアダプター、そして認証された接続を持っている場合には、結果を確認することもできます。シェルを利用できるエージェントは、MCPの設定画面なしで、CLIやHTTPゲートウェイを使用することができます。

このガイドでは、**OpenAI Dots**、**Grok Bot**、**Meta Muse**（個人用のエージェント）、そして**Manus Cue**について説明しています。これらのプラットフォームに関するドキュメントは、Lightboxの開発やデプロイメントを行う際に使用されるコンピュータ上で別途記録されています。Lightboxとは、ここでの開発やデプロイメントのための環境です。DCC-MCPがアプリケーションの統合を行っています。このコンピュータから得られる結果は、すべてのアカウント、画像、プラットフォームに対してサポートを提供するわけではありません。これらは独立した統合であり、どのプラットフォームとの提携関係があるわけではありません。

## 接続を選んでください。 {#choose-a-connection}

1. エージェントのクラウドコンピュータでの使用については、サポートされているローカルアダプターやCLI、またはその環境のMCPクライアントを使用します。まずは、どのアプリケーションやアダプターのバージョンを使用するかを確認してください。ネイティブAPIは、統合候補を特定するのに役立ちます。次に、型付けされたアダプターの利用が考えられます。
2. **承認されたワークステーションでの使用：** DCCエンドポイントをループバックモードに設定し、承認されたコンピュータ接続や保護されたゲートウェイを通じて接続します。クラウドエージェントは、目的のプロジェクトやアーティファクトへのアクセスが必要です。また、ワークステーションは常に利用可能でなければなりません。
3. **Shell対応のエージェント:** `dcc-mcp-cli`を使用して、インベントリの管理やツールの検索を行います。ネイティブなMCPコンフィギュレーションUIはオプションです。Command MCPとCLIは別々のインターフェースです。Coreの`translate`ブリッジは`stdio → HTTP`を介して通信します。クライアントのCommandサポートは、DCCのstdioワークフローを実現していません。

ネットワークをまたぐ場合は、**前段のプロキシまたは専用の OAuth ゲートウェイで TLS と認証を設定**してください。アクセス先を制限し、DCC はループバックのみにバインドします。[Core 0.20.39 の認証仕様](https://github.com/dcc-mcp/dcc-mcp-core/blob/v0.20.39/docs/guide/remote-server.md#auth) では、`McpHttpServer` によるリクエスト単位の Bearer/OAuth/CIMD の強制は計画段階です。`ApiKeyConfig` と `OAuthConfig` だけでは実行時のアクセスを制御できません。認証を設定していないエンドポイントをそのまま公開しないでください。

## インストールに必要な前提条件 {#prerequisites}

- 選択した環境でソフトウェアをインストールしたり、更新したりするための許可が必要です。また、利用可能なターゲットアプリケーションや、必要なライセンスも用意されている必要があります。DCC-MCPプラグインには、アプリケーションやそのライセンス、またはパブリックなマルチテナントエンドポイントは含まれていません。
- アダプターがサポートする範囲内のアプリケーション版であり、ネイティブライブラリが必要であり、また、公式なアダプターであるか、明確に記録されているソースパッチが必要です。
- 互換性のあるCLI/MCP接続、利用可能なライブインスタンス、そして認可されたプロジェクトディレクトリが必要です。GUIに依存するツールについても、プラットフォームが提供する管理型デスクトップやサポートされている表示サービスが必要です。
- リモートでの使用の場合、利用可能なTLS/認証基盤が必要であり、秘密情報はオペレーターによって管理されます。このガイドでは、公開エンドポイントや認証情報の設定は行いません。

[共有エージェントの設定](/ja/agents)および[アダプターディレクトリ](/ja/ecosystem)に従ってください。インストールに関する説明や、ホストごとのトラブルシューティングについては、アダプターリポジトリで確認できます。

## 確認を伴うワークフロー {#verified-workflow}

まず、タスクによって割り当てられたドキュメントと、1つの処理を開始します。例えば、CADパーツを確認したり、寸法を変更したり、そのデータを保存したり、再度開いて寸法を確認したり、STEP形式にエクスポートする前に確認を行ったりします。これは受け入れパターンです。上記のマトリックスでは、実際にどの実験が成功したかが示されています。

```bash
# After approved setup, inspect the current environment and live instances.
dcc-mcp-cli doctor
dcc-mcp-cli list

# Only continue when a ready instance for the intended application exists.
dcc-mcp-cli search --query "inspect document" --dcc-type freecad

# Follow the returned next_step and exact schema; do not invent a tool slug.
```

在库存が空であったり、インスタンスが準備ができていない場合は、その処理を停止する必要があります。アプリケーション/アダプター/Coreのバージョン、接続ルート、パッチのソースコミット情報、リクエスト/ジョブのID、アーティファクトのチェック情報などを保持しておく必要があります。保存やエクスポートされた内容は、ネイティブドキュメントを再開するか、出力結果を独立して確認することで確認する必要があります。失敗したジョブのIDを保持しておき、それを無視してミューテーションを再実行しないようにしてください。

```text
dcc-mcpスキルを使用して、選択されたクラウドコンピュータや認可されたワークステーション上にあるタスクに関連するドキュメントを確認します。バージョンや準備状況を確認し、必要なツールを使用して変更を行います。結果を保存し、再度開いて確認します。エクスポートされたアーティファクトも確認してください。ソフトウェアをインストールしたり、システムの状態を変更する前には必ず報告してください。接続ルートやその他の情報も報告してください。
```

## よくある質問 {#faq}

### これは、4つのプラットフォームすべてが、すべてのDCCをサポートしているという意味ですか？

No. プラットフォームのインターフェース、インストールされているソフトウェア、アダプターの受け入れは、別々に行われます。Grok BotやMuseでは、統合の方法が記載されていますが、DCCテストについては何も記載されていません。Cueの必要なインターフェースについても、まだ確認されていません。たとえテストが通過したとしても、それは記録されたバージョンやワークフローにのみ適用されます。

### DCC-MCPを、ネイティブなMCPの設定画面なしで使用することは可能ですか？

はい、エージェントがシェルアクセスを許可している場合、正常に動作する`dcc-mcp-cli`があり、ローカルまたは保護されたHTTPゲートウェイが利用可能であることを確認してください。また、そのプラットフォームが必要な実行や接続を許可しているかどうかも確認が必要です。シェルだけでは、アプリケーションをインストールしたり、ライセンスを取得することはできません。

### なぜ、ネイティブ実行が成功する一方で、MCPは失敗するのでしょうか？

ネイティブのコマンドでは、アダプターの処理が失敗したり、結果の検証ができなかったり、ジョブの追跡やソースの確認ができなかったりすると、ファイルを作成することはできません。FreeCADやInkscapeでは、これらの問題が発生しても、ワークフローやアーティファクトが正常に読み取られるまで、アダプターの失敗は解決されていないとみなされます。

### クラウドエージェントは、私のライセンス付きのデスクトップDCCと連携して動作することができますか？

認可されたパーソナルコンピュータ接続や、保護されたゲートウェイを利用すれば、そのようなルートを提供することができます。アクセス可能かどうか、サポートされているバージョン、経路、ワークステーションの可用性、ライセンスについては、運営者と確認してください。プラットフォームのドキュメントでは、すべてのデスクトップDCCを保証しているわけではありません。

### このページは、AI検索の際に、確実に目に留まるようになるでしょうか？

No. [GoogleのAI検索ガイドライン](https://developers.google.com/search/docs/appearance/ai-features)では、通常に見つけられる、読みやすいコンテンツや、構造化されたデータの照合が必要とされています。特別なAIファイルやスキーマは不要であり、索引化や表示も行われません。[OpenAIのクローラーに関するドキュメント](https://developers.openai.com/api/docs/bots)では、検索用のクローラーとトレーニング用のクローラーとの違いが説明されています。このガイドラインは、サイトの既存のクローラーポリシーを維持します。
